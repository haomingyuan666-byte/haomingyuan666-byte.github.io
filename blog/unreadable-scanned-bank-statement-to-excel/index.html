How to Handle Unreadable Pages in a Scanned Bank Statement

November 16, 2026

If your search is “unreadable scanned bank statement to Excel,” start by identifying which page is missing from the export and what you can actually read on it. Record the page as a coverage exception as soon as ordinary extraction fails. Then choose whether someone should verify recognized text against the image, enter the visible rows by hand, or ask the client for a clearer source.

Keep the exception open until its contents have been checked against a readable page. If the rest of the workbook needs to move ahead first, put the incomplete coverage status where the recipient will see it and name the affected page. A recipient can review the pages already checked while leaving tasks that require the full statement pending.

Check the transaction area on each page

Open the original PDF and work through it in file order. On each page, try selecting a date, a description, and an amount from a visible transaction. Paste the selection into a working note and compare the resulting text with the image on screen. A selectable page heading is only evidence about that heading. The body can still be a scan, and a page with recognition text can yield incorrect characters or leave part of a row inaccessible. Inspect the actual transaction area before marking the page as readable.

Record what you observe. A page may yield usable transaction text, show a legible image without selectable text, or contain an image whose amounts cannot be read confidently. If the page visibly contains summary material or terms, note its role once you have inspected it. Use “unresolved” when you cannot determine whether the page contains transactions. A blank extraction result by itself gives you no evidence that the page had nothing to contribute.

Use the position in the PDF as the primary locator and capture the printed page label if it differs. A cover page or an inserted image can make those references diverge. Someone opening the original attachment should be able to find the page from the log even if the PDF viewer displays a different numbering convention. Keep the locator when making a cropped working copy so the crop can be traced back to the complete page.

Make the coverage gap visible in the workbook

In Hao Studio's conversion test, a bank statement contained 30 transactions. Page 4 was an image-only scan with no text layer. The converter parsed the remaining pages and flagged the scan in both Checks and Needs Review. The coverage check returned FAIL as designed, giving the reviewer a reason to look for the exception despite the successful extraction on the other pages.

Use a page log with a row for every page in the PDF. Record the file reference, page locator, what you could read, current status, and who will take the next action. On an unresolved page, describe the failure plainly. A note such as “transaction table visible in image, no selectable line text” gives the next reviewer enough information to try recognition. A note such as “amount column cut off at the edge” points toward a replacement source instead. Put a short coverage summary near the front of the workbook and keep the detailed actions in the review list.

Choose a route for the unreadable page

Review optical character recognition against the image

Use optical character recognition, or OCR, when the image is readable to a person and contains enough of the transaction area to review the result. Keep the extracted text with the source page reference. Compare it with the image row by row and look for changes that still resemble plausible entries, such as a missing minus sign, a shifted decimal, or a date joined to a description. Check the edge of each row and where text wraps, because the recognized values may be individually legible while appearing beside the wrong transaction.

Keep uncertain fields flagged until the reviewer can resolve them from the image or a replacement source. If recognition produces a partial table, record which part still requires attention. Ask the reviewer to confirm the full page against the PDF before closing the exception. An OCR run can produce text without supplying enough evidence to call the page recovered.

Enter rows by hand when the image is legible

Choose manual entry when a person can read the source but the recognition output makes it hard to match values with their rows. Keep the source visible while entering the transactions into a working sheet with their page references. Record that the rows were transcribed and identify the fields that need a second look. During review, read from the source back to the sheet. That direction helps the reviewer notice a visible line for which the worksheet has no entry.

If a field is genuinely unreadable, mark it as unresolved in the review list and describe what is obscured. Leave an uncertain amount out of any total that the recipient might treat as final. After verifying the transcription, append the reviewed entries with their source references and keep a note of the method. Use that note to answer later questions about why those rows were handled differently from the rest of the file.

Ask the client for a clearer source

Ask for a replacement when the page is cropped, blurred, or otherwise unreadable even after direct inspection. Name the statement and the page locator using the client's established delivery channel. Describe what is missing and ask for the original downloadable statement or a complete, legible scan of the affected page. Mention which edge or column needs to be visible if that will help the client produce the right replacement. Keep the request linked to the existing exception so a later reply has a clear destination.

Compare the replacement with the original before adding any rows. Check that it covers the same account section and statement period and that the visible material belongs at the intended location. If the client sends a replacement for the full statement, confirm that the page order still matches your log. Keep the original and the replacement distinguishable in your records, and point the review note to the file that supplied the recovered entries.

Label a handoff with an open exception

If you need to share a partial workbook, make the coverage status visible in the workbook summary and in the handoff message. State which page is unresolved, whether it was excluded from the transaction sheet, and what action is pending. A message for the test case could read, “Coverage incomplete. PDF page 4 is an image-only scan and is still open in Needs Review. The other pages were parsed. Keep statement-wide totals and reconciliation pending until page 4 is verified.” Use wording that reflects the file you are actually delivering.

When the page is resolved, record who checked it and where the recovered entries came from. Refresh the coverage summary and share the revised workbook with a note identifying the resolved exception. If you need help with an unreadable statement, include the source file, the page reference if known, and whether you need a reviewed partial workbook while the replacement is pending.
